# Astro Synapse design

Clickable prototypes for every project. Designers vibe-code the UI/UX here; front-end developers build the real product from it.

Everything is reachable from one page, `index.html` in the repo root. Open it straight from disk, serve it with `python3 -m http.server`, or publish it with GitHub Pages.

## Structure

```
README.md
build.py                 builds index.html from build.json
build.json               the projects, and exactly what to build for each
page.html                the page shell build.py fills in
frame.js                 the shared script every site page includes
index.html               generated by build.py and committed: the one page with everything
.context/
  instructions/          agent primers and instructions (pick the one for your agent; nothing is loaded automatically)
  history/
astrosynapse.ai/         one folder per project, named after its domain
  website/
mcs.hr/
  website/
webagen.astrosynapse.ai/
  renderers/             this project's component renderers and their CSS
  website/
  templates/
    website/             a webAgen template
    webshop/
```

Two kinds of things can be built:

- **Website**: a classic multi-page site. A folder with `index.html` and the other pages, `styles.css`, `main.js` and `public/`. The main page shows it in a clickable frame with a page list, back/forward, an address bar, desktop/mobile and open in a new tab.
- **Template**: a webAgen template the agent builds pages from:

  | File | What it holds |
  |---|---|
  | `README.md` | what the template is |
  | `design.md` | colours, type, spacing, graphics, UI elements |
  | `components.md` | the sections the agent can send: ruleset and JSON for each |
  | `content.md` | the facts the agent answers from |
  | `layouts/` | example flows, one `.md` per flow |
  | `prototype/` | the template's clickable site, built like a website |
  | `prompts/` | AI instructions for the template |

  The main page gives each template these tabs: Prototype, Design, Components (with a download of every ruleset and JSON example as one `.md`), Example layouts and Content. Component previews are drawn by the project's renderers.

## Building

Run this before every commit that changes a site, a template, a renderer or `build.json`:

```
python3 build.py
```

Then open `index.html` to check, and commit it with your changes. The build prints a warning for:

- invalid JSON;
- a layout that uses a component the template doesn't have;
- a link to a missing file;
- a site page without the `frame.js` tag.

## build.json

The build only reads what is listed here. Nothing is detected automatically.

```json
{
  "title": "Astro Synapse design",
  "projects": [
    {
      "id": "webagen",
      "title": "webAgen",
      "build": [
        { "id": "website", "type": "website", "title": "Website", "path": "webagen.astrosynapse.ai/website" },
        {
          "id": "website-template", "type": "template", "title": "Website · Astro",
          "path": "webagen.astrosynapse.ai/templates/website",
          "renderers": ["webagen.astrosynapse.ai/renderers/astro.js", "webagen.astrosynapse.ai/renderers/astro-kit.js"],
          "theme": "astro",
          "styles": "webagen.astrosynapse.ai/renderers/astro-base.css",
          "tailwind": "webagen.astrosynapse.ai/renderers/twlite.py"
        }
      ]
    }
  ]
}
```

| Field | Used by | Meaning |
|---|---|---|
| `id` | project, item | used in the page address, e.g. `index.html#/webagen/website-template/components`; unique within its project |
| `title` | project, item | shown in the top bar (project) and the bar below it (item) |
| `type` | item | `website` or `template` |
| `path` | item | the folder, from the repo root |
| `renderers` | template | JS files that draw the components from their JSON; components without one show a wireframe |
| `theme`, `styles` | template | the CSS the renderers use, under the theme name they declare (`theme: "astro"`) |
| `tailwind` | template, optional | a `twlite.py` that adds the Tailwind utility classes the renderers use to `styles` |

## Adding a project or a site

1. **Folder:** create the project folder (e.g. `mcs.hr/website/`) with an `index.html` and the other pages.
2. **Script tag:** add the shared script to every page, just before `</body>`. Its path is relative to the page: one `../` per folder level up to the repo root.

   ```html
   <script src="../../frame.js"></script>
   ```

   It tells the main page which page is open. Opened on its own, the page ignores it.
3. **List it:** add the project and the item to `build.json`.
4. **Build and commit:** run `python3 build.py`, check `index.html`, and commit.

## Publishing

GitHub Pages: Settings → Pages → Deploy from a branch → `master` / `(root)`. It serves the committed `index.html`; no Actions needed.
